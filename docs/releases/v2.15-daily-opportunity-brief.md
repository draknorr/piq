# v2.15 — Custom Daily Steam Opportunity Brief

**Date:** July 27, 2026

**Current release gate:** the Opportunity performance path from PR #97 and the
customer-ready browser contract ship together from one reviewed revision. The
additive migrations `0097`, `0098`, and `0099` already exist in production and
are not part of this application rollout. Completion requires the query API,
single Railway worker, and Vercel admin to report the same final source
revision, followed by one natural daily run with a single attempt, settled
queue work, non-empty phase timings, and runtime inside the performance
envelope. No historical `why_now` backfill or external email/Slack destination
is included.

## What shipped

- A new `/opportunities` sourcing workspace and canonical per-result game record.
- Eight immutable PublisherIQ v1 presets plus user-owned cloned or blank
  profiles.
- Required, preferred, excluded, ANY, and ALL rule groups backed by one
  tri-state preview/evaluation model.
- Durable newly discovered, newly released, newly qualified, subscribed
  material-change, and tracked-update handling.
- Readiness waiting, retries, dead letters, deduplication, dismiss/ignore/track,
  and event-driven reappearance.
- Versioned rank, cohort, market, materiality, rule, signal, and preset-health
  evidence.
- Shared viewed/researching activity with personal profile and game state.
- Canonical website delivery plus encrypted, idempotent email and Slack
  summaries, local-time scheduling, profile-scoped destinations, and explicit
  truncation notices.
- A reproducibility ledger exposing matched profile versions, run/event/source
  timestamps, calculation versions, source watermarks, and delivery history.
- Exact customer-readable before/after change evidence on daily results and
  recent game changes, with truthful null/sparse-evidence fallbacks.
- Workspace name and owner/admin/member role in canonical game records, with
  operational data status hidden from members by default.
- Plain-language opportunity fit, comparable-game benchmarks, rule evidence,
  and Steam metric labels while retaining technical provenance behind
  owner/admin details.
- Versioned evaluation-input/cohort projections, exact persistent cohort cache,
  source-revision fences, bounded bulk persistence, and per-run phase timings.
- A continuous Railway worker and separate approval-gated, bounded GitHub event
  reconciliation workflow.

## Architecture

Supabase remains the authentication and session authority. Tiger holds the
complete opportunity transaction domain and Steam evidence. The browser reaches
Tiger only through authenticated query-api contracts. Delivery channels project
stored website results and do not recalculate them.

The release is additive:

- `0097_opportunity_mvp.sql` adds the versioned Tiger schema.
- `0098_opportunity_preset_seed.sql` adds the eight launch preset versions.
- `0099_opportunity_evaluation_performance_v1.sql` adds the optimized,
  source-fenced evaluation and persistence path.

The migrations were applied during explicitly approved production windows.
They are never applied automatically and must not be reapplied during an
application-only release.

## Evidence and calibration

Market labels use conservative thresholds selected from a read-only 50,000-game
production sample. Preset-health movement thresholds remain provisional because
the inspected signal-window sample was sparse. See
[Opportunity v1 calibration](../reference/opportunity-calibration-2026-07-27.md).

Production rollout and recovery evidence, including PRs #87–#91, deployment
IDs, bounded batch timings, the production rule preview and daily evaluation,
the source-provenance follow-up, and the explicitly accepted live-delivery
boundary, is in
[Opportunity production rollout closeout](../reference/opportunity-production-rollout-closeout-2026-07-27.md).

## Explicit deferrals

- automated developer outreach;
- deal stages or CRM workflows;
- guaranteed market-size or revenue claims;
- automatically generated, published, or enabled preset recommendations;
- semantic-only comparable cohorts;
- immediate alerts for existing-game breakthroughs;
- historical profile replay before a sufficient run ledger exists; and
- treating incomplete YouTube coverage as a universal filter or negative signal.
